## 明确未打通项：摄像头原生推流

对 vision/classroom_monitor.py 第 296 行的 async_send_stream_report，提取当前源码中的真实方法并运行，避免加载 GPU/摄像头依赖；只将构造参数 backend_url 指向本次独立真实后端。输入合成零人帧，HTTP 传输没有模拟或替换。

实际请求 POST /api/visual/report/stream 返回 HTTP 401（未登录或令牌过期）。发送方法只有 Content-Type，没有 Authorization；第 428 行构造的 payload 也没有 offeringId。错误在 except Exception: pass 中被吞掉。后端已要求有效认证和明确班次，本次已另行验证缺少班次的已认证请求返回 400。

关联入口 frontend/src/api/index.ts 第 74 行的 startMonitor 不传班次参数；frontend/dev/camera-plugin.mjs 第 112 行左右启动 Python 时没有传递用户认证和班次上下文。上述源代码判断与真实 401 一致。即使本机摄像头或模型正常运行，也不能据此认为数据能进入当前受权限保护的考勤大屏。

这次仅检查，没有自动扩大为代码修复。后续需要贯通浏览器所选班次、受控认证、Python 发送与停止流程，并在真实摄像头条件下复测。不能通过放开后端鉴权来代替接入整改。

## 既有修复保持有效

- 三角色未授权班次的实时概览/趋势/学生状态、推流、重置均 403，拒绝请求不增加数据库记录；同名班次缓存及重置相互隔离。
- 冻结班次三角色写入 409，按钮只读；旧页面启动失败后不推流，运行中归档后停止；真实 MySQL 行锁并发冻结后没有新增记录。
- 教师/督导只读本班名单，候选库为空，页面不显示选入移出按钮；主任名单操作及人数同步有效。旁听编号不泄漏其他班级学生姓名/头像，空名单人数为 0。
- PDF/DOCX/PPTX 原件下载类型和字节一致，教师本人及主任可下载，共享教师及督导拒绝原件下载。
