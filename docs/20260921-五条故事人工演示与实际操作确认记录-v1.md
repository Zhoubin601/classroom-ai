## 二、 逐条故事实操细节与断言日志记录

### 故事一：US-01 主任导入课程
- **操作流程**：
  1. 浏览器打开 `http://127.0.0.1:5173`，使用教研室主任账号 `director` 登录，进入专属工作台。
  2. 点击顶部操作栏“批量导入课程 (US-01)”按钮，弹出标准化导入对话框，内含全院专业编码速查字典。
  3. 点击“下载空白模板”，网络监听确认请求发往 `/api/v1/courses/import/template`，HTTP 状态码为 `200`，请求头携带有效 `Bearer` JWT 令牌。
  4. 构造标准规范 CSV 文件（新增专业核心课 `DEMO-SE88`《新工科敏捷协同实战》），注入文件上传框，系统触发 `/api/v1/courses/import/preview` 预检解析，弹窗呈现 1 条待导入记录预览。
  5. 点击“确认导入并整批入库 (US-01)”，弹出 alert 确认成功导入，课程归属教研室与学院完全合规。
  6. 页面自动回刷并在课程档案表格中直观检索到新增课程代码 `DEMO-SE88`。
- **验证结论**：通过，全流程符合主任角色管辖边界，无绕过或越权风险。

### 故事二：US-02 教师草稿与发布
- **操作流程**：
  1. 在 Playwright 中创建隔离的 BrowserContext A 与 Context B，同时模拟任课教师 `guojun` 登录两个独立窗口。
  2. 窗口 A 编辑课程简介并点击“暂存草稿”，后端乐观锁版本升级为 `1`。
  3. 窗口 B 保持旧状态尝试保存草稿，后端捕获版本陈旧异常，返回 HTTP `409 Conflict`，前端弹出“检测到并发修改冲突(版本不一致)”错误提示，成功阻断脏写覆盖。
  4. 窗口 A 补齐考核方式与教学目标后点击“正式发布”，系统将草稿固化为正式版 `v1`，发布人与发布时间均留痕。
  5. 窗口 A 在已发布 `v1` 基础上再次暂存草稿，通过外部公开读取接口验证：读者只读接口仍稳定返回正式版 `v1`，未发布的草稿内容实现严格读者隔离。
  6. 窗口 A 执行二次“正式发布”，版本升级为 `v2`。
- **验证结论**：通过，草稿暂存、并发防覆盖（409）、读者隔离与版本递增（v1 ➔ v2）全部闭环。

### 故事三：US-03 主任多教师排课
- **操作流程**：
  1. 主任登录进入“开课与排课”看板（`OfferingScheduleBoard`）。
  2. 针对《软件项目管理》（计科2024-1班），点击“编辑班次”，在协同教师多选区勾选“姜琳颖 · T2024002”，保持选课名单不变，点击保存。任课团队即刻刷新为“郭军（主讲）、姜琳颖（协同）”，选课人数保持无损。
  3. 点击“新增排课”，选取已排在周三第 3-4 节的班次，尝试在相同周三第 3-4 节安排在另一教室（信息馆 B201），点击保存。后端即刻返回 HTTP `409 Conflict`，排课弹窗内渲染红色“冲突详情”区域，详细指出该教师在此时段已被占用。
  4. 点击取消关闭弹窗。利用筛选工具栏按学期“2026-2027秋季”和教室“文管 A447”执行组合筛选，精准定位卡片。
  5. 点击卡片“编辑排课”，将教室更改为“文管 A448”后保存，排课接口正确排除该排课记录自身的主键 ID，更新成功（HTTP 200）。随后重置筛选并恢复原排课数据保持系统清洁。
- **验证结论**：通过，协同教师团队维护、名单留存、跨教室时段冲突 409 拦截与自排除更新逻辑严密准确。

### 故事四：US-04 结课后历史人数
- **操作流程**：
  1. 主任在开课班次列表中找到已完成教学周期的《软件项目管理》，点击“结课归档”，浏览器弹出归档二次确认框，自动点击确认。
  2. 归档完成后，该班次状态变为“已归档”，原有的“编辑班次”与“结课归档”按钮被物理隐藏。
  3. 主任尝试绕过界面、通过底层接口 `/api/v1/courses/offerings/1/students/add` 强行修改已归档班次名单，后端校验到 `isSnapshotFrozen = true`，直接阻断并返回 HTTP `409 Conflict`，保证历史档案不可篡改。
  4. 切换为任课教师 `guojun` 登录，教师工作台“历史开课与人次”看板立即加载出已归档班次，选课人数严格基于固化快照展示，累计上课人次准确累加。
  5. 在历史学期输入框中输入不存在的学期（如 `2099未知学期`）并点击查询，列表展示“暂无历史开课记录”，累计人次自动归零（`累计人次 0`）。点击“清空条件”恢复全量历史展示。
- **验证结论**：通过，物理与逻辑双重冻结生效，防篡改 409 有效，历史人数与累计人次口径完全符合教务规范。

### 故事五：US-06 督导组合检索与权限
- **操作流程**：
  1. 督导专家 `supervisor` 登录，切换至“待督导目标课程多维检索 (US-06)”标签页。
  2. 检查“授权专业”下拉选框，仅渲染该督导被授权的“软件工程 (SE)”、“计算机科学与技术 (CS)”，未授权的“人工智能 (AI)”、“数据科学 (DS)”被物理隔离剔除。
  3. 执行多维 AND 组合检索：选择专业“软件工程”、教师“郭军”、学期“2026-2027秋季”、关键字“软件项目管理”，系统秒级过滤并呈现目标卡片，主讲教师高亮置顶。
  4. 输入不存在的关键字“不存在的课程XYZ”，卡片区域即时展示“未检索到符合条件的待督导开课信息”规范空状态。点击“清空检索条件”，列表恢复展示首批待督导开课，并显示“共检索到 11 门待督导开课”。
  5. 越权攻击校验：使用督导身份 Token 向后端未授权专业接口发起请求（`GET /api/v1/courses/offerings?majorCode=AI` 与 `majorId=3`），后端均精准抛出并响应 HTTP `403 Forbidden`；使用未登录匿名请求访问 `/api/v1/courses/offerings/history` 亦被拦截响应 HTTP `401 Unauthorized`。
- **验证结论**：通过，多维 AND 检索体验流畅，专业授权隔离与越权 403 拦截严密可靠。
