# 当前项目 UI 评审

日期：2026-10-09。依据用户指定的 ui-ux-pro-max 技能，对当前 Vue 3 + Tailwind 页面进行源码检查及真实 Chrome/Playwright 检查。

结论：页面已有较统一的浅底卡片、图标和角色导航，主要问题集中在弹窗可用性、编辑保护、窄屏布局和信息层级。建议先修复会阻断操作或丢失内容的问题，再调整视觉。以下优先级为本次评审建议，不代表用户已确认改版方向。

## 检查范围与证据

- 浏览器连接现有 `http://127.0.0.1:5173` 前端；角色为主任、教师、督导。
- 检查登录页，以及主任课程档案、教师工作台、督导默认课表、考勤、学生档案页面。五个登录后页面分别检查 1440×900、768×1024、375×812、667×375；登录页检查桌面。另检查减少动态效果设置。
- 交互专项：新增课程弹窗、上传课件弹窗、Tab/Esc、未保存文本切换页面，以及拦截课程 GET 请求返回 503 的失败状态。
- 证据文件：`docs/20261009-ui-review-evidence-v1/measurements.json`、`supplement.json` 与页面截图；复现脚本为 `docs/20261009-ui-review-browser-v1.cjs`、`docs/20261009-ui-review-supplement-v1.cjs`。
- 所有业务写请求由浏览器路由拦截；仅放行登录/退出认证 POST 与 GET/HEAD/OPTIONS。打开考勤页面自动触发的 `/api/visual/reset` POST 已拦截。未提交课程、资源、评价或考勤修改；未采集学生档案截图，未保存认证凭据。
- `raw/` 只有 `README.md`，独立设计稿与目标设备资料未提供。使用当前源码、现有过程记录、已存在的设计规范和技能本地数据；未联网使用外部资料。

P1：优先修复，涉及操作阻断、内容丢失或基础交互可访问性。P2：影响效率、理解和阅读。P3：设计规范治理及后续一致性。

## P1：优先处理

### 1. 弹窗相对内容区定位，窄屏下表单落到屏幕外

**实测确认。** 新增课程弹窗在桌面上的遮罩顶部为 188px，而不是视口顶部。375×812 下，表单顶部为 854px、底部为 1516px，整个表单落到可见屏幕下方；667×375 下顶部为 729.5px。截图 `director-modal-375.png` 能看到遮罩和背景导航焦点，但看不到表单。

位置：`frontend/src/App.vue:101`、`frontend/tailwind.config.js:62`、`frontend/src/views/DirectorDeskView.vue:448`。

原因：`main` 的 `animate-fade-in` 使用 `forwards` 保留 `transform`，浏览器计算值为 `matrix(1, 0, 0, 1, 0, 0)`；其内部 `fixed` 遮罩因此相对变换后的内容容器定位。课程表单自身也未设置高度上限与内部滚动。教师上传弹窗同样位于该内容容器内，源码存在相同风险。

建议：将模态弹窗通过 Vue `Teleport` 挂到 `body`；统一 `max-height`、内容滚动和底部操作区，避免让入场动画的变换长期留在弹窗祖先上。验收应覆盖桌面、375px、横屏，确认遮罩覆盖视口且取消/保存始终可达。

### 2. 切换工作台会静默丢失未保存的课程编辑

**实测确认。** 在教师课程简介输入临时测试文本，切到考勤，再返回教师工作台，输入不再保留，全程没有离开提醒。测试未点击保存或发布。

位置：`frontend/src/App.vue:102`、`frontend/src/views/TeacherDeskView.vue:290`、`:1304`。

原因：工作台通过 `v-if/v-else-if` 卸载重建；编辑状态在组件内，新建组件重新读取服务端草稿。切换课程时也会重置表单，但该分支本轮只做源码检查。

建议：增加未保存变更检测，离开前提供“继续编辑 / 放弃 / 保存后离开”；或按课程保留会话内编辑状态。验收需验证切换工作台、切换课程、重新拉取草稿及保存失败后的文本保留。

### 3. 主任、教师、考勤页面在 375px 出现整页横向溢出

**实测确认。** 文档实际宽度分别为主任 463px、教师 554px、考勤 535px，超过 375px 视口。学生与督导默认页面本次未出现整页溢出；不能据此推断全部子页面通过。

位置：`frontend/src/views/DirectorDeskView.vue:74`、`frontend/src/views/TeacherDeskView.vue:42`、`frontend/src/views/AttendanceDashboardView.vue:33`。

触发点包括不换行的搜索+筛选组合、长课程选择器，以及考勤选择器的 `min-w-[280px]` 与旁边标签共同占宽。表格容器内部横向滚动本身可以接受，当前问题是表格外控件撑宽了整页。

建议：窄屏将筛选和课程选择改为纵向排列；父级及子控件使用 `min-width:0`、`width:100%` 和合适的最大宽度，长标签提供可操作的完整值查看方式。验收要求整页不横向滚动，保留必要的表格内部滚动。

### 4. 弹窗没有完整的键盘交互，上传入口也无法用 Tab 到达

**实测确认。** 主任新增课程、教师上传弹窗的 `role=dialog` 数量均为 0；新增课程打开时焦点留在背景，下一次 Tab 到了背景的“专业全量课程档案”按钮；两个弹窗按 Esc 后仍保持打开。上传拖拽区为 `DIV`，`tabIndex=-1`、无交互角色，其文件 input 为 `display:none`。

位置：`frontend/src/views/DirectorDeskView.vue:448`、`frontend/src/views/TeacherDeskView.vue:608`、`:624`。`OfferingScheduleBoard.vue:241` 已有 dialog 语义，可保留，但这不等于具备完整焦点管理。

建议：共用模态组件，统一可访问名称、初始焦点、焦点限制、关闭后焦点恢复、Esc 和背景不可交互。上传区使用原生按钮或可聚焦且有名称的文件输入入口，保留鼠标拖拽功能。未实测所有弹窗，不能将两个代表弹窗的问题等同于全部弹窗均失败。

### 5. 多处可见表单标签未与输入控件关联

**实测 DOM 确认。** 登录页 2/2、主任默认课程页 3/3、教师页 4/8、督导默认页 5/5、考勤页 1/1、学生页 1/1 个可见输入/选择控件没有关联 label 或 `aria-label/aria-labelledby`。计数是各默认页面的样本，不是全项目比例。

位置：`frontend/src/views/LoginView.vue:117`、`frontend/src/views/TeacherDeskView.vue:286`、`frontend/src/views/DirectorDeskView.vue:76` 等。

建议：有可见标签时用 `for/id` 或包裹控件的 label；无可见标签的紧凑筛选补充可访问名称。错误信息与字段关联，异步提示提供适当的播报语义。已有 `aria-label` 的控件无需重复改写。本轮未使用真实屏幕阅读器，不宣称完成其行为验收。

## P2：效率与阅读问题

### 6. 请求失败被呈现成“没有数据”

**通过模拟故障确认。** 主任课程 GET 返回 503 后，页面显示“未找到符合条件的课程档案”，可见错误提示和重试按钮均为 0。这是浏览器拦截生成的失败响应，不是后端实际故障。主任 `loadCourses` 仅写控制台；学生列表和督导统计加载有类似 catch 分支，后两者未做本轮故障注入。

位置：`frontend/src/views/DirectorDeskView.vue:1259`、`frontend/src/views/StudentManageView.vue:884`、`frontend/src/views/SupervisorDeskView.vue:1119`。

建议：明确区分加载中、成功为空、失败、保留旧数据；失败给出重试，保留旧数据时说明未刷新。不能只显示服务在线就暗示当前业务数据已成功加载。

### 7. 小字号与浅灰文字叠加，阅读负担较大

**实测确认。** 主任和督导主体文字常见 10/11/12px；教师历史说明为 12px，实际前景 `rgb(148,163,184)`，背景白色，按相对亮度计算对比度为 **2.56:1**，低于技能的普通正文 4.5:1 检查基准。

位置：`frontend/src/components/OfferingHistoryPanel.vue:16`、`frontend/src/App.vue:38`，以及各页面 `text-[10px]` / `text-[11px]`。

建议：主体阅读与表单文字优先 14px，次要说明 12px；关键说明和操作文字使用更深的语义颜色。字号是设计建议，不将“低于14px”直接判作标准违规。这里只验证了一个实际配色，不宣称所有浅灰文字均不合格。

### 8. 全局导航在窄屏占据太多高度，短文字被拆行

**实测确认。** 375px 下主任 sticky header 高 217px，督导为 257px；加上顶部状态条，主体分别从 300px、340px 才开始。横屏 667×375 下主任主体从 248px、督导从 260px 开始。身份、退出、在线状态在窄屏被压成多行，增加滚动成本。

位置：`frontend/src/App.vue:7`、`:26`、`:61`。

建议：窄屏保留品牌、当前工作台和账户入口，将身份详情和其他工作台收进菜单；状态栏压缩展示，避免“退出登录”等短操作拆行。主任页面四个顶部动作可将常用主操作突出，其余放入次级操作区。

### 9. 教师首页将完整历史表放在当前教学任务之前

**视觉检查确认，改法属于设计建议。** `OfferingHistoryPanel` 位于整个教师页第一项。1440×900 截图中，当前教师/课程区域约在 y=673px 后才出现；375px 第一屏几乎都用于历史区，上传课件、课程编辑和教学反馈需要继续滚动。

位置：`frontend/src/views/TeacherDeskView.vue:3`。

建议：先呈现当前课程、当前任务和主要操作，将历史统计移至独立页签、折叠区或页面后部。历史记录是否为主要演示任务，待用户后续确认；不要直接删除这项功能。

### 10. 导航选中状态只有视觉变化，页面位置也没有 URL 表达

**DOM 与源码确认。** 三角色全局导航按钮均未设置 `aria-current/aria-selected/aria-pressed`；页面切换仅更新组件内 `activeTab`，刷新时按角色重置到初始工作台，无法分享某个具体工作台链接。子导航也应按实际导航语义选择标记，不必将所有按钮强制改成 ARIA tab。

位置：`frontend/src/App.vue:43`、`:147`、`:194`、`:222`。

建议：普通导航采用链接/路由和 `aria-current`；若采用 tab 组件，则完整实现 tab/tabpanel 与对应键盘行为。保留课程筛选和当前工作台状态，让刷新与返回行为可预测。

### 11. 操作反馈与点击区域缺少统一规范

**源码与尺寸测量确认。** 教师保存/发布/资源维护大量使用浏览器 `alert/confirm`，成功提示混入 MySQL、并发锁版本等实现术语。主任表格“大纲”按钮实际点击区域为 24×16px；小区域与相邻编辑/删除操作增加误点风险，但本轮未做用户误点实验。

位置：`frontend/src/views/TeacherDeskView.vue:1351`、`:1398`、`frontend/src/views/DirectorDeskView.vue:152`。

建议：成功用页内状态或统一 toast，字段错误就地显示，危险操作使用清楚说明对象与后果的确认弹窗；给表格操作留足内边距和间隔。小尺寸结果不自动等于标准违规，是否有足够间距等例外需逐项验证。

界面还持续展示 JWT、JPA、MySQL、US 编号等技术词。课程演示可能需要这些标记，建议做显式演示模式；业务模式使用任务语言，是否保留演示标记待确认。

### 12. 减少动态效果设置未得到响应

**实测与源码确认。** 督导默认页正常模式与 `prefers-reduced-motion: reduce` 下仍均有 2 个运行中的动画；全局样式未见减少动态效果规则。持续 pulse 与进入动画应按用户设置减弱。

位置：`frontend/src/App.vue:10`、`frontend/tailwind.config.js:62`、`frontend/src/style.css`。

建议：通过媒体查询关闭装饰性的循环动画和位移动画，保留必要状态文字。不能只依靠动画区分在线/加载状态。本轮未验证真实动态数据图表。

## P3：规范一致性

### 13. 已有设计规范与实现没有形成一致的约束

**本地文件对照确认。** `design-system/classroomai/MASTER.md` 指定主色 `#1E3A5F`、CTA `#A16207` 和衬线字体；实现主色变量为 `#4F46E5`，页面广泛使用 indigo/emerald/amber，字体为系统无衬线。现有规范是否正式确认，资料未提供，因此这里记录为文档与实现的差异，不判定紫色或系统字体本身错误。

位置：`design-system/classroomai/MASTER.md:18`、`frontend/src/style.css:8`、`:15`、`frontend/tailwind.config.js`。

建议：先确认当前轻量管理台风格，再统一主操作、危险操作、文字、边框、间距、按钮与弹窗规范。中文后台不宜仅因生成文件提到学术风格，就强制换成英文衬线字体。

## 建议实施顺序与限制

1. 修复弹窗定位与焦点管理，补可达的上传入口。
2. 修复未保存内容的离开保护，消除整页横向溢出，关联表单标签。
3. 补加载失败/重试状态，调整文字对比度、导航高度与教师任务顺序。
4. 统一反馈、导航状态、减少动态效果及设计规范。

保留现有已按角色过滤的导航、Lucide 图标体系、表格内部滚动、历史统计中的口径说明，以及已存在的权限/错误提示。Demo 全量 CSV 与主任学生底库为已确认业务口径，不作为本轮 UI 缺陷。

待用户复核：主要使用设备、当前教学任务与历史数据的优先级、技术演示标记的保留范围、设计规范是否为正式版本。这些不阻塞本次现状评审，但会影响后续改版方案。

未完成范围：本轮只评审，未改业务 UI 源码；未穷举全部子页/弹窗，未做真实屏幕阅读器、200%缩放、硬件摄像头和实际视频播放验收。无正式 Office 文件需求，评审及证据留在 docs/，未将未确认改版稿放入 output/。
