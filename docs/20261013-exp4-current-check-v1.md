## 1. P1：返回资源版本页时，旧加载响应可以覆盖新选择

位置：`frontend/src/components/ResourceVersionsPanel.vue:24–26,34–36`。

复现步骤：

1. 主任在“统计与反馈 → 资源版本”选择资源101（系列10）。
2. 切到“质量汇总”，再返回“资源版本”。组件保留资源101的选择，并在 mounted 中自动加载其历史；延迟该历史响应。
3. 自动加载期间，选择资源201（系列20），其历史先成功返回。
4. 资源101的旧响应随后返回。下拉框仍选中201，历史表却被覆盖成系列10。
5. 点击“设为当前版”，实际发出 `PUT /api/v1/resources/series/10/current`，请求中的版本为102，属于旧资源。

原因：用户主动切换通过导航协调器串行处理，但 mounted 的恢复加载不受该串行处理保护；history 无请求代次、资源ID一致性及卸载检查，返回结果直接写入 data。selectVersion 和 upload 均以 data 中的系列确定操作对象。

影响：用户同时具有两个系列的权限时，可能在错误界面上下文中切换旧系列的当前版本。后端仍执行原系列权限检查；本次没有证明越权。错误写请求在本地 API 夹具中捕获，没有写入业务库。上传同样使用旧 data，是源码风险，未另行实测上传误操作。

建议：为历史加载建立独立请求代次并捕获所请求资源ID；只提交与当前选择一致的最新响应。加载时清空旧历史并禁止写操作，卸载撤销请求；写入前核对选择与历史所属系列。回归必须覆盖“恢复已记忆选择 → 自动加载未完成 → 选择另一资源”的场景。

证据：`20261013-exp4-current-check-v1/resource-history-race-final.log`、`resource-history-race.json`、`resource-history-race.png`；复现脚本 `resource-history-race.cjs`。使用合成账号、资源和本地响应。
