## 实现与修复

### US-02

- 教师页面独立课程简介区域，三项内容、暂存、发布、发布状态、发布人/时间及草稿更新时间；与工程认证大纲区分。
- 沿用数据库乐观锁版本、草稿 ID、基准发布版本联合校验；发布三项必填，仅关联任课教师可操作。
- 两个浏览器分别加载同一草稿，先保存者成功，旧页面提交收到 HTTP 409 并阻止盲目重试。
- 草稿 → 发布 v1 → 再次编辑暂存 → 读者继续看到 v1 → 发布 v2 流程通过；发布工号、时间可追溯；未发布返回空正式版本。
- 普通课程编辑、导入及旧大纲接口不覆盖这三项正式发布内容的既有保护通过回归。

### US-03

- 主任班次新增/编辑支持课程、学期、教学班、主讲教师、协同教师、选课名单；教师及学生使用真实字典记录，人数从名单计算，关联记录在同一事务替换。
- 排课列表支持学期、教师（含协同）、周次、教室组合筛选，展示全部教师、周次和节次区间；新增、编辑、删除均经过服务层范围检查，写操作还受主任角色路由门禁保护。
- 相同学期、重叠周次/星期/节次，只要教室相同或教师工号有交集即冲突；补上同一班次不同教室重叠漏检，排除同名不同工号误报；编辑仅排除自身，禁止借他班记录 ID 绕过检查。
- 修改教师或学期，保存前校验全部已有排课（含同班次内部重叠），任一冲突则整个班次、教师与名单变更回滚。
- 移除 `String.intern()` / `synchronized`，使用 InnoDB `t_academic_term_lock` 行；先锁班次，再按规范化学期排序锁定，READ_COMMITTED 读取最新已提交排课，学期锁持有至事务提交。
- 冲突返回 HTTP 409 和完整 `data.conflicts` 数组；页面显示原因、课程、全部教师、教室、学期及时间区间。
- 旧选课增删入口同步改为主任权限、班次行锁与冻结校验，避免绕过新班次维护入口或用旧实体覆盖更新。
