## 为什么再次整理

第一次重构完成了代码职责划分，但仍保留多份根目录启动入口、零散日志、独立测试目录、旧服务空目录和历史备份，文件浏览器中仍有 33 项。按照用户本次要求，将这些辅助内容收拢后，根目录剩 16 项：12 个目录、4 个文件。

这是实际文件迁移，没有通过隐藏文件来制造整洁效果，也没有删除用户文件。依据是用户截图和本地源代码；raw 原始资料没有移动或修改。

## 为防止移动后失效，修改了什么

1. 前端摄像头适配器：共享图片读写改到 `runtime/uploads/`，监控日志改到 `runtime/logs/`。
2. Python：`vision/paths.py` 统一指定新的共享图片位置。
3. Java：上传接口与静态图片映射共用 `UploadPaths`；从项目根目录或 `backend/` 启动均落到同一个运行数据目录，也支持 `CLASSROOM_UPLOAD_DIR` 覆盖。
4. Docker：构建目录改为 `../../backend`，SQL 初始化路径改为 `./mysql/init`，共享图片挂载至容器，保留既有数据库卷名称和原项目名称。
5. 启动器：仅在根目录保留 `start_project.ps1`；实际逻辑在 `scripts/`，部署统一通过 `scripts/compose.ps1` 定位配置。
6. 测试与 SQL 生成器：更新移动后的资源定位；SQL 生成器按自身位置定位输出，整理过程没有运行生成器或改写现有 SQL 数据。
7. `.gitignore`：忽略 `runtime/` 和 `docs/archive/`，避免运行图片、日志和备份进入源码版本控制。

## 今后怎么启动

从项目根目录执行 `./start_project.ps1` 启动全部组件。单独启动前端用 `./scripts/start_frontend.ps1`；视觉监控用 `./scripts/run_monitor.bat`；Docker 状态用 `./scripts/compose.ps1 ps`；自动化验证用 `./scripts/run-tests.ps1 -Offline`。

原根目录分模块启动命令不再作为入口。不要运行 archive 内的旧脚本。先前已启动的进程需重启后使用新源码，本次没有强行关闭进程。
