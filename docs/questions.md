# 需要用户确认的关键技术细节与问题 (Questions)

在编写 Java 后端（Spring Boot + Redis + MySQL + Docker）人脸数据存储模块前，梳理以下设计细节与选择供确认：

## 1. 人脸特征向量存储格式与计算分工
* **当前方案（推荐）**：
  * **MySQL**：使用 `MEDIUMTEXT` 保存 512 维浮点数 JSON 数组 `[0.0123, -0.0456, ...]`。
  * **Redis**：缓存每个学生的 512 维特征向量，提供快速查询与全量同步。
  * **计算分工**：
    * **模式 A（主流边缘计算）**：Python 视觉端/机器人端在启动时通过 `GET /api/face/all` 从后端一次性同步特征库到内存，由本地 GPU 继续做实时余弦相似度比对（极低网络开销，延迟 < 5ms）。
    * **模式 B（云端中心比对）**：Python 端仅抽取特征向量后 `POST /api/face/search` 发送给 Java 后端，Java 后端从 Redis 遍历特征计算余弦相似度并返回姓名与置信度。
  * **本方案设计**：同时实现模式 A 与模式 B，满足边缘实时与云端检索双重需求。

## 2. 人脸注册上传形式
* 接口支持：
  1. **直接传输特征向量**（Python 算法端已用 InsightFace 提取出 512 维 embedding，直接发 JSON 数组 `featureVector` 入库，最高效）；
  2. **上传人脸照片附件**（可选 `MultipartFile` 文件上传，后端保存到本地上传目录，记录 `image_path`）。

## 3. 容器化编排环境
* `docker-compose.yml` 编排：
  * `mysql`：版本 8.0，端口 3306，自动挂载初始化 SQL 脚本。
  * `redis`：版本 7.2-alpine，端口 6379。
  * `classroom-backend`：基于 Java 21 的 Spring Boot 服务，端口 8080。
