## 严格验收差距与证据

### US-09：预览安全通过，但水印样式和交互保护不足

全量文档第 125～126 行要求水印包含单位、查看人及只读凭证，采用半透明倾斜样式，并禁用右键另存、复制。

实际转换 PDF 中的水印为 `PREVIEW guojun 时间戳`。没有单位名称；PDF 内容流使用灰色文字和平移，没有水印旋转或透明度配置。对应代码：`backend/src/main/java/com/classroom/ai/modules/resource/service/ResourceFileService.java:85`。资源元数据中的单位水印不等于预览文件中真正渲染了该水印。

教师预览使用普通 PDF iframe（`frontend/src/views/TeacherDeskView.vue:707`），并提供鉴权下载原件。对 iframe 派发可取消的 contextmenu 事件后 `defaultPrevented=false`；PDF 没有 Encrypt 权限设置，可直接提取文本。当前访问鉴权、防直链、票据过期已通过，但不能据此宣布“禁另存/复制”通过。

证据：`supplement-results.json`、`pdf-protection-inspection.json`、`converted-docx.pdf`、`converted-pptx.pdf`，均在本轮证据目录。

### US-14：三条亮点标准未受约束

全量文档第 161 行要求课堂亮点“3条以上”。补验将 `highlights` 填为“仅一条亮点”，先保存草稿，再正式提交，实际返回业务码 200、状态 PENDING_REVIEW。后端只检查非空及 500 字上限（`SupervisionServiceImpl.java:108`），没有条数检查。建议按正式验收口径明确结构化条目或等效校验。

### US-05：需要同步验收文档口径

全量文档第 84 行写“一键套用12项国标推荐模板”。实际教师页面该按钮数量为 0，使用“从培养方案创建大纲”，只接受主任导入的专业及版本目录（`TeacherDeskView.vue:437`）。后者符合 docs/source-notes.md 中较新的实施口径，也避免编造真实指标。应在正式验收清单中说明采用哪个口径；不能将模板条款静默标为通过。

## 验证边界

- 当前 raw 只有 README，未提供真实培养方案、原始实验一规划 DOCX、评审/回顾材料。本轮使用已记录的八故事范围及仓库全量需求文档，未声称重新读取历史 Windows 路径的原始资料。
- 匿名发布仅推进本轮临时容器中该条测试评价的发布时间；应用仍使用默认24小时规则。真实等待24小时及正式团队评审需要另行事实复核。
- 预览截图捕获 iframe 挂载，但 PDF 区域为暗色，不能把截图当成浏览器已显示正文与可翻页的证据。PDF正文和水印通过解析实际响应文件核验。原生 PDF 对照检查受到云端浏览器 file URL 管理策略限制，故视觉翻页保留为未确认项，不判成后端转换失败。
- 本轮不包含真实摄像头/GPU、生产数据或 Windows 启动入口。
- 八故事脚本执行时，转换命令仍指向不存在的路径，损坏 DOCX 预览返回422。因此该断言证明转换异常被拒绝，不能单独证明损坏文件识别正确。修正命令后有效 DOCX/PPTX 的真实转换均通过；损坏文件在正确转换环境中未补跑，保留为未完整验证项。
