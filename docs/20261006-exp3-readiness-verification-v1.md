### 本地修正与失败原因

1. 审核卡片：旧 CSS 类定位无法适配用户已修改的样式；在 DirectorDeskView.vue 添加评价 ID 的 data-testid，exp3-real-browser.cjs 使用同一 ID。后端审核行为未改，完整 8 条复测通过。
2. 排课表单：新版 OfferingScheduleBoard.vue 的 10 个输入缺少可访问名称，补齐 aria-label；保留用户现有布局与样式。真实排课新增、冲突、编辑、组合筛选、95 人名单流程通过。
3. 权限测试：现有 CourseAuthorizationService、CourseAuthorizationPrimaryTeacherTest 明确支持旧库缺关联表记录时的主讲 teacherCode 授权，主讲编号由主任维护。旧 legacyTeacherDisplayFieldDoesNotGrantAccess 测试删除关联记录却保留主讲编号，导致断言矛盾。校正为只保留展示姓名，并新增主讲可读、同名不同编号教师不可读的 MySQL 用例；21 项通过。没有修改权限业务代码或放宽拒绝断言。
4. 历史浏览器脚本：旧“单元格包含已归档”匹配到了空态说明中的“已归档或开课班次”，未等真实记录加载；改为精确等待“已归档”状态。脚本兼容当前下拉学期控件与旧输入控件，选择无记录学期仍检查空表和人次为 0。完整五故事复测通过。
